## 站点标题

科研上下文助手 —— 每句话都能回到原文

## 副标题（一句话）

读了几十篇论文，结论记不住、引用找不到源头，隔几天还接不上。这个工具让检索结果带上证据编号，
证据不够的地方直接告诉你「这里没覆盖」。

## 一、解决的问题

做科研最常见的三件事：读了一堆论文，结论记不住；写东西时想引用，找不到是哪篇哪段；
换个时间接着做，前面的进展要重新翻一遍。

现有的 AI 助手能给出漂亮的总结，但你没法确认那些总结是从哪来的。
**这个工具反过来做**：不生成结论，只把证据原文摆出来，并明确标注哪里证据不足。

## 二、核心功能

**1. 文献入库，每块可溯源**
把 Markdown / 纯文本的论文按段落切块，存进 seekdb，每一块都记录内容哈希。
（配图：`bash run.sh ingest` 的输出截图）

**2. 提问即检索，结论挂引用**
输入研究问题，系统把它拆成子问题，逐个子问题检索证据。
报告里每条结论后面带 `[E1]`、`[E2]` 编号，对应到具体的文献、段落和原文片段。
（配图：报告「结论与证据」段的截图）

**3. 证据边界：没覆盖就直说**
每个子问题按证据条数与文献数判定状态：证据充分 / 证据不足 / 证据单一 / 语料未覆盖。
后三种会汇总到「证据缺口」表，附带缺失的关键词。
（配图：报告「证据缺口」段的截图 —— 这是本项目最有辨识度的一张图）

**4. 自检：引用可以逐条回查**
`bash run.sh verify` 会解析报告里每一个证据编号，逐条回数据库读取证据块，
比对 sha256 与原文。任何一条对不上就报失败。
（配图：verify 全绿 + 故意改错 sha256 后报失败的对比截图）

**5. 状态可复用：重启后接着干活**
研究任务的问题、子问题、已积累证据、未解决缺口都写进 PowerContext。
重启服务后 `resume` 能读回状态与报告，并在下一次提问时带上「上次任务进展」。
（配图：`restart` + `resume` 的输出截图）

## 三、技术分工

| 技术 | 承担什么 |
| --- | --- |
| **seekdb**（嵌入式） | 存文献证据块与关键词；检索时把查询条件下推到 SQL 执行；报告里每条证据都从它读回 |
| **PowerContext** | 存研究任务状态与报告正文，重启后读回复用 |
| **Qoder** | 完成全部编码、调试与测试，并通过 Qoder Sites 发布本网站 |

## 四、一次完整演示（30 秒看懂）

研究问题：**如何降低嵌入式数据库中文档检索的延迟**

拆成 4 个子问题后：

- 「索引结构」「检索延迟预算」→ 找到多篇文献的交叉证据，给出带 `[E1]`…`[E6]` 的结论；
- 「分布式部署」「GPU 加速」→ 语料基本不覆盖 → 如实标成缺口（语料未覆盖 / 证据单一），并列出缺失关键词。

（配图：完整报告截图，重点圈出缺口表）

## 六、已知边界

- 不调用大模型：结论只来自检索到的原文，因此不会替你「总结成一段话」；
- 只支持 Markdown / 纯文本，PDF 需先转换；
- 中文按二元组匹配，同义词改写可能召回不到；
- 单机单用户，未做并发控制。

> 如实写边界比夸大能力更容易通过评审 —— 题面也要求「已知限制」写进运行说明。
