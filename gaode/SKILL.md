# 周边去哪儿：地点推荐助手

## 1. 适用场景

单轮任务：用户在某个起点附近找一类地点，并希望步行可达。

- 输入包含：城市、起点（优先使用给定的经纬度；没有坐标时用地址）、地点类型（咖啡馆/餐厅/公园等）、步行时间上限（分钟）、推荐数量（默认最多 3）、偏好（如"优先近一点"）。
- 所有推荐都从**同一起点**独立出发，不串成多站行程。
- 本 Skill 只负责"查询 → 筛选 → 推荐"，不负责设备定位、长期记忆或多轮协商。

## 2. 执行流程

### 第 1 步：解析需求

从用户话语中抽取以下字段，缺失的用默认值或按合理范围处理：

| 字段 | 说明 | 缺省处理 |
| --- | --- | --- |
| 起点 | 经纬度优先；否则用地址 | 若两者都没有，先向用户追问 |
| 地点类型 | 关键词，可含细分（如"手冲咖啡""安静的咖啡馆"） | 必填 |
| 步行上限 | 分钟数 | 未说明时按 20 分钟筛选，并在回答中注明假设 |
| 推荐数量 | 条数 | 默认最多 3 条 |
| 偏好 | 近、评分高、连锁/独立等 | 默认按步行时间升序 |

若起点是地址而非坐标，先调用**地理编码**能力（常见工具名 `maps_geo` / `geocode`）转为经纬度，再进入搜索。

### 第 2 步：地点搜索

按能力选择工具，不要硬编码工具名（不同客户端暴露的名字可能是 `maps_around_search`、`around_search` 等，以实际加载的高德工具为准）：

1. **周边搜索**（优先）：以起点坐标为中心，`keywords` 填地点类型，`radius` 由步行上限换算。
   - 换算规则：按步行约 4.5 km/h，取 `半径(米) ≈ 上限分钟 × 75`，并向上留 20% 余量，最大不超过 5000 米。例：15 分钟 → 约 1350 米。
2. **关键词搜索**（兜底）：周边搜索无结果或结果明显不足时，用 `keywords + city` 扩大范围，仍以起点为中心人工过滤距离。
3. 对候选结果调用**详情搜索**（`maps_search_detail` / `search_detail`）补齐坐标、地址、类型，剔除类型明显不符的条目。

候选池控制在 5~8 个：先按直线距离取近的，再按评分/热度补充，保证有足够样本进入路线核验。

### 第 3 步：步行路线核验

对每个候选地点调用**步行路径规划**（`maps_direction_walking` / `direction_walking`），参数：

- `origin` = 起点经纬度
- `destination` = 候选地点经纬度

记录返回的 `distance`（米）与 `duration`（秒或分钟，按工具返回值换算）。**步行时间必须来自这次路线查询，禁止用直线距离或速度估算替代。**

### 第 4 步：筛选与排序

按顺序应用硬条件：

1. 剔除步行时间超过用户上限的地点（超时地点不能作为"符合条件"的推荐）。
2. 剔除类型不符、坐标缺失或路线查询失败的地点。
3. 按偏好排序：用户说"优先近一点"时按步行时间升序；否则可按步行时间为主、距离/评分为辅。
4. 截取前 N 条（默认 N=3）。

### 第 5 步：生成回答

用 Markdown 表格或编号列表，每条包含：

| 地点名称 | 地址 | 预计步行距离 | 预计步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- |

要求：

- 推荐理由只能基于已获得的数据（类型匹配、步行时间、距离、评分、地址特征），一句话即可。
- 表格后补一句总述（如"以上 3 家均在 15 分钟步行范围内，按步行时间由近到远排序"）。
- 不输出高德原始 JSON，不罗列无关字段。

## 3. 异常与边界处理（必须遵循）

| 情况 | 处理方式 |
| --- | --- |
| 符合条件的地点不足 N 个 | 只推荐已有的，明确说明"范围内仅找到 X 个符合条件的地点" |
| 周边搜索无结果 | 扩大半径或改用关键词搜索；仍无结果则如实说明，并建议放宽类型/时间/范围 |
| 工具调用失败 / 超时 | 如实告知"高德服务本次查询失败"，不编造地点；必要时说明已尝试的范围 |
| 地点存在但路线查询失败 | 该地点不作为合格推荐，或列入"未核验步行时间"的附注，不计入推荐数量 |
| 营业状态、排队、安静程度、人均价格等无数据 | 一律标注"未核实"，不得编造或推断为事实 |
| 用户给的是地址且地理编码失败 | 说明无法定位起点，请用户补充坐标或更具体的地址 |

## 4. 禁止事项

- 不得编造地点名称、地址、坐标或步行时间。
- 不得用直线距离、地图比例尺或经验速度替代步行路线查询结果。
- 不得把超出步行上限的地点列为符合条件，也不得先推荐再"补充说明其实超时"。
- 不得为凑数量而推荐类型不符或无法核验的地点。
- 不得在输出中包含任何 API Key、请求地址或内部工具凭证。

## 5. 输出模板

```
根据你在<起点>附近、步行不超过<上限>分钟、找<类型>的需求，为你推荐以下 <N> 个地点（按步行时间由近到远）：

| 地点 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- |
| ... | ... | ... 米 | ... 分钟 | ... |

说明：<结果数量不足 / 服务异常 / 部分信息未核实 等情况，如无则省略>
```
